## 3. 로드맵 재구조화

기존 #4 구조를 유지하되 다음을 조정한다:

1. **#16 "주간 세금"과 Phase 3 "자산 누진세"는 통합** — 설계상(07) 주간 세금이 곧 자산 누진세라 분리 구현이 불가능하다. 누진세는 Phase 2로 흡수하고, Phase 3의 #17은 신뢰도·재분배·긴급지원에 집중한다.
2. **#17의 Phase 2/3 중복 기재 정리** — 신뢰도 시스템 전체를 Phase 3로 일원화. 단 **weeklyDAU 집계 축적은 Phase 2 정산 잡에 선행 탑재**한다(#17의 신뢰도 공식이 주간 DAU를 입력으로 요구하므로 데이터가 미리 쌓여야 함).
3. **신규 항목 추가** (기존 로드맵 누락분):
   - 스케줄러 인프라 전환 (Phase 2 선행 과제)
   - 공장 로스터 완성 5종 (D-3)
   - 토지 구역 2+ 구매 (`docs/design/11` — 설계 존재, 로드맵 부재)
   - 배포 파이프라인 (D-4)
   - 경제 밸런스 시뮬레이터 (#21의 선행 도구)
4. **#20 웹 대시보드는 Phase 6에서 분리해 병렬 트랙(W)으로 조기 이행** — 봇 DB 읽기 전용이라 봇 개발과 충돌이 없고, 로그인→404 문제가 이미 사용자에게 노출되는 상태다.

> 실행: 플랜 확정 후 `roadmap-sync` 스킬로 이슈 #4 본문 갱신 + 신규 이슈 생성.

### Phase 4 — 주식

**선행: 스키마 보강 마이그레이션** — 현재 스키마로는 설계 요구를 못 채운다:

- `Stock.dividendRate` 부재, `StockHolding.avgBuyPrice`(손익 계산 필수) 부재
- 종목별 체결량 집계 불가(TradeLog에 stockId 없음) → `stockId` 컬럼 추가 또는 별도 체결 로그
- `Stock.weeklyProfit`을 채울 공장 수익 집계 파이프 부재 → 수확·판매 시 수익 적립 경로 설계

이후: 상장(자동 검증 — 자산 평가 로직 재사용, **상장 단위는 스키마 현행대로 "공장"** — 유저가 자기 공장을 상장, 설계 문서의 유저/공장 혼선은 문서 쪽 통일), 매매 커맨드, 1시간 가격 tick 잡(0-나눗셈 가드 — §6 U-5), 주간 배당(2.5 정산 잡 확장), 일일 ±30% 서킷브레이커.

**Exit**: 상장→매매→배당 1주기 완주, 가격 tick이 체결량에 반응.

## 5. 병렬 트랙 (Phase와 독립 진행)

세션을 나눠 병렬로 진행 가능한 작업들. 우선순위: **Q > D > W > I > O** (돈 경로 보호 → 설계 블로커 해소 → 사용자 노출 버그 → 출시 준비 → 관측).

### 트랙 Q — 품질 (Phase 2와 동시 시작)

- **Q-1** CI에 Postgres 서비스 컨테이너 추가 → 통합 테스트 편입. _현재 돈이 오가는 마켓 경로가 머지 전 자동 검증되지 않는다 — 최우선_
- **Q-2** apps/bot vitest 커버리지 설정 + 게이트 (services/ 부터 80%)
- **Q-3** apps/web 단위 테스트 (korean-tokenizer, serialize 등 순수 로직 — 현재 0건)
- **Q-4** Playwright e2e를 nightly CI로

### 트랙 D — 설계 문서 정리 (Phase 2 착수 전 1차 완료)

- **D-a** 오늘 결정 4건 반영 (§2)
- **D-b** 모순 11건 수정 (§6 상단) — 기본 방침: **코드 현행 = 진실, 문서를 맞춘다** (예외: 명백한 문서 오류는 문서 수정)
- **D-c** Phase 2 블로커 미정의 사항 확정 (§6 U-1 ~ U-7)

### 트랙 W — 웹 (Phase 2~3와 병렬, #20 조기 이행)

- **W-1** 로그인 콜백 404 즉시 해소 (Step 5 착수 전이라면 콜백을 `/`로 임시 변경)
- **W-2** 플랜 파일 Step 5 실행: `/onboarding`(봇 미가입 분기), `/dashboard`(개인 — 내 공장·자산·XP), `/leaderboard`(**공개** 랭킹 — middleware 보호 대상에서 제외), `lib/game.ts`(AuthAccount.accountId→게임 User 연결), `lib/serialize.ts`(BigInt 직렬화 헬퍼 — 문서만 있고 구현 부재)
- **W-3** 서버별 통계 (Phase 3 신뢰도 데이터 등장 후 확장). 랭킹 캐싱은 tick 주기에 맞춘 revalidate(10분)부터, 필요 시 Redis
- **W-4** AGENTS.md 최신화 (Next 16.2.4·React 19.2.5 반영 — 현재 15.3/thin scaffold로 기술돼 에이전트가 낡은 전제로 작업할 위험)

### 트랙 I — 인프라·배포 (Phase 3 완료 전까지)

- **I-1** Dockerfile 재작성: `node:20-slim` + corepack(pnpm 10.9) + `turbo prune` 멀티스테이지. _기존 apps/bot/Dockerfile은 node:16+yarn 유물로 빌드 불가_
- **I-2** `compose.prod.yml`: bot·web·postgres·redis + 볼륨·헬스체크
- **I-3** GitHub Actions 배포: GHCR 이미지 빌드 → VPS 배포 → `prisma migrate deploy` 단계 (현재 CI에 migrate 자동화 없음)
- **I-4** pg*dump 백업 크론 + 복구 리허설 1회. *경제 데이터 유실 = 게임 신뢰 붕괴\_

### 트랙 O — 관측성 (Phase 3 전까지 최소셋)
